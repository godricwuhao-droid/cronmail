# ADR-022: 机柜 U 位点阵式点位图（替代 ADR-021 点位图方案）

## Status
Accepted（Supersede ADR-021 中"U 位不入库存 / 机架卡片网格点位图"的决策）

## Context
ADR-021 的卡片式点位图（机架卡片 + 设备清单）上线后，用户反馈不符合设计需求：需要类似机房巡检 Excel 的**U 位点阵图**——列=机柜、行=U 位（1~N 自下而上编号）、每格显示一台设备（型号/用途/IP），颜色区分状态（绿=在用、红=断电/故障、灰=空位），一眼看清每个机柜每格存放情况。这要求 U 位必须结构化入库（此前 rack_location 自由文本 + 前缀匹配的方案无法支撑格子级渲染）。

## Decision
1. **设备 U 位结构化**：`RentalRecord` 增加两列
   - `rack_id`（Integer，可空，无硬 FK，指向 rack 表）
   - `u_position`（Integer，可空，1~capacity_u）
   - 点位图数据完全由 `machine_room_id + rack_id + u_position` 驱动；`rack_location` 文本列**保留但不再用于点位图**（存量数据兼容，新表单不再展示）
2. **唯一占用约束**：同一机架内同一 U 位只能有一台设备（API 层校验，冲突 409）；本期每设备占 1 格（不建模多 U 跨度——参考图均为单格设备，避免过度设计）
3. **点位图数据**：`GET /api/machine-rooms/{id}/points` 扩展，每个机架返回 `u_cells: [{u, rental_id, machine_model, remark, private_ip, status}]`（1..capacity_u 全量行，空格设备字段为 null）
4. **前端点阵图**：机房详情页渲染**多机柜并排表格**——表头=机架名，行=U 位（capacity 最大值向下到 1），单元格按状态着色：`已断电`→红、`租赁中/空闲中`→绿、空→灰；格内显示 型号 / 备注(用途) / 内网IP，小字多行；点击格内设备跳设备详情
5. **设备表单**：所属机房下拉 → 机架下拉（按机房联动过滤）→ U 位数字输入（1~capacity_u，可空）；409 冲突提示"该 U 位已被占用"

## Consequences
**变容易的**：
- 点位达到格子级精度，与用户心智模型（巡检表）一致
- U 位占用可校验（防双设备挤一格），机架容量统计精确

**变难的**：
- 存量 22 台设备只有 rack_location 文本、无 rack_id/u_position，点位图上线后存量设备全部显示"未上架"，需人工在表单里逐台指定机架+U 位（一次性整理成本）
- 每设备限 1U：真有多 U 设备（GPU 服务器常见 2U/4U）暂时无法表达格子占用——列为已知限制，出现真实需求再加 u_count
- 再次加列需一次性 DDL（asset_ops 库）

## 可逆性
高：加可空列 + 展示层改造，回滚 = 前端隐藏点阵图，列留空无害。

## 决策记录
- 2026-10-07：用户提供 Excel 点位图样例，要求格子级精度；ADR-021 点位图方案作废，本 ADR 生效
