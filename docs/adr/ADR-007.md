# ADR-007: 算力服务合同服务行字段增强（GPU + 服务描述）

## Status
Proposed

## Context

当前 `ContractServiceLine` 只支持 CPU 算力场景（vcpu_count/memory_gb/storage_gb），无法描述 GPU 算力实例（GPU 卡数、型号、显存、算力），也缺少长文本服务描述字段。同时规格参数（specification）使用了预设模板，存在与结构化字段重复的问题。

## Decision

### 1. 新增 5 个字段

在 `contract_service_line` 表新增：

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `service_description` | TEXT | NULL | 服务描述长文本，所有大类通用 |
| `gpu_count` | INTEGER | NULL | 每台 GPU 卡数 |
| `gpu_model` | VARCHAR(100) | NULL | GPU 型号（A100/H800） |
| `gpu_memory_gb` | NUMERIC(10,2) | NULL | 单卡显存 GB |
| `gpu_tops` | NUMERIC(10,2) | NULL | 单卡算力 TOPS |

### 2. 计费公式不变

`total_price = quantity × period_months × unit_price`

GPU 也是按台计费，GPU 相关字段仅用于展示和统计。

### 3. GPU 统计能力

| 统计指标 | 公式 |
|---------|------|
| 总 GPU 卡数 | `SUM(quantity × gpu_count)` |
| 总显存 | `SUM(quantity × gpu_count × gpu_memory_gb)` |
| 总算力 | `SUM(quantity × gpu_count × gpu_tops)` |

### 4. 规格参数去模板化

前端删除 `SPEC_TEMPLATES` 预设，默认空数组，用户按需添加 key-value。切换大类不清空已有参数。

### 5. 隔离约束

- 仅修改 `compute_service` 模块（算力服务合同）
- 不触碰 `contract` 模块（算力租赁合同）
- 不触碰邮件通知模块

## Consequences

### 变容易了
- GPU 实例配置可完整录入和展示
- 可按 GPU 卡数/显存/算力做运营统计
- 服务描述提供自由文本补充空间
- 规格参数无冗余，用户自主控制

### 变难了
- 新增迁移文件，需更新部署
- 前端表单复杂度增加（GPU 区域条件显示）

## Reversibility
**高** — 所有新字段均为 NULLABLE，不影响存量数据。回滚只需删除迁移和前端隐藏对应区域。
