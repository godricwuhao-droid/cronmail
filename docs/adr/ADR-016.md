# ADR-016: 项目管理模块（独立合同台账+附件归档）

## Status
Proposed

## Context

业务方需要为三个公司主体（蜂云时代、安徽天枢、千星控股）分别建立合同台账和附件归档功能，与现有合同管理体系完全独立。

核心约束：
1. 数据与现有合同管理（算力租赁/卫星数据/算力服务）**物理隔离**—独立数据库表
2. 代码与现有模块**零耦合**—不 import 任何现有合同模块
3. 三个公司主体共用功能，通过 `company_code` 做数据隔离

## Decision

### 1. 数据模型（独立新表）

```sql
-- 项目管理合同主表
project_contract
  id            CHAR(36) PK
  company_code  VARCHAR(20)   NOT NULL  INDEX   -- fengyun / tianshu / qianxing
  name          VARCHAR(255)  NOT NULL          -- 合同名称
  contract_no   VARCHAR(100)  NULL              -- 合同编号
  contract_type VARCHAR(30)   NOT NULL  DEFAULT 'sales'  -- sales / procurement
  party_a_name  VARCHAR(255)  NULL              -- 甲方
  party_b_name  VARCHAR(255)  NULL              -- 乙方
  amount        DECIMAL(12,2) NULL              -- 合同金额
  start_date    DATE          NULL              -- 开始日期
  end_date      DATE          NULL              -- 结束日期
  related_contract_id CHAR(36) NULL  FK→self   -- 背靠背关联（仅关联同表内合同）
  project_name          VARCHAR(255) NULL       -- 所属项目
  contract_content      TEXT         NULL       -- 合同内容
  delivery_requirements TEXT         NULL       -- 交付要求
  process_records       TEXT         NULL       -- 过程记录
  remark         TEXT         NULL
  sort_order     INT          NOT NULL DEFAULT 0
  created_at     DATETIME     NOT NULL
  updated_at     DATETIME     NOT NULL

-- 服务行子表
project_service_line
  id              CHAR(36) PK
  contract_id     CHAR(36)    NOT NULL  FK→project_contract CASCADE
  category        VARCHAR(50) NOT NULL
  item_name       VARCHAR(100) NOT NULL
  specification   JSON        NULL
  vcpu_count      DECIMAL     NULL
  memory_gb       DECIMAL     NULL
  storage_gb      DECIMAL     NULL
  gpu_count       INT         NULL
  gpu_model       VARCHAR(100) NULL
  gpu_memory_gb   DECIMAL     NULL
  gpu_tops        DECIMAL     NULL
  unit            VARCHAR(20) NOT NULL
  quantity        DECIMAL     NOT NULL
  period_months   INT         NOT NULL DEFAULT 1
  unit_price      DECIMAL     NOT NULL
  total_price     DECIMAL     NOT NULL
  sort_order      INT         DEFAULT 0
  service_description TEXT    NULL
  created_at      DATETIME    NOT NULL
```

### 2. 附件隔离

- 新增 `contract_type = 'project'`
- 默认三个分类：合同材料(`contract_material`)、交付材料(`delivery_material`)、过程材料(`process_material`) 
- 三个公司共用，通过 `contract_type=project` 与现有附件隔离
- 附件配置页支持按 `contract_type` 筛选，前端菜单增加「项目管理附件配置」入口

### 3. 代码组织（零耦合）

```
backend/src/project/        ← 全新模块，零 import 现有合同
  ├── models.py
  ├── schemas.py
  ├── services.py
  ├── api.py
  └── prompts.py           ← 智能解析 Prompt（字段名适配 project 表）

frontend/src/views/projects/
  ├── index.vue            ← 列表页
  ├── form.vue             ← 创建/编辑页
  ├── detail.vue           ← 详情页
  └── AttachmentsPage.vue  ← 附件管理页（如共用则复用，否则独立）
```

### 4. API 端点

```
GET    /api/project-contracts?company=fengyun&search=&page=&page_size=
POST   /api/project-contracts
GET    /api/project-contracts/{id}
PUT    /api/project-contracts/{id}
DELETE /api/project-contracts/{id}

GET    /api/project-contracts/export?company=fengyun         ← Excel 导出
POST   /api/project-contracts/{id}/service-lines/batch       ← 服务行批量保存

POST   /api/contracts/parse?contract_type=project             ← 智能解析（复用端点，新增 project prompt）
GET    /api/attachments?contract_type=project&contract_id=    ← 附件（复用）
GET    /api/attachments/export?contract_type=project&...      ← 附件导出（复用）
```

### 5. 前端路由 + 菜单

```
/projects
├── /fengyun    → 蜂云时代合同列表
├── /tianshu    → 安徽天枢合同列表
└── /qianxing   → 千星控股合同列表
  ├── /create   → 新建（hidden）
  ├── /:id      → 详情（hidden）
  ├── /:id/edit → 编辑（hidden）
  └── /:id/attachments → 附件管理（hidden）
```

菜单：
```
项目管理
├── 蜂云时代
├── 安徽天枢
└── 千星控股
```

### 6. 功能清单

|------|:--:|------|
| 合同 CRUD | ✅ | |
| 服务行（service_lines） | ✅ | 与算力服务合同一样 |

| Excel 导出 | ✅ | 按 company 过滤 |
| 附件管理 | ✅ | contract_type=project |

## Consequences

### 变容易了
- 项目管理与现有合同管理完全解耦，后续任一方的字段变更互不影响
- 新增公司主体只需加枚举值 + 菜单项 + 路由，改动量极小
- 附件通过 contract_type 天然隔离

### 变难了
- 新增两张表 + 一整套 CRUD 代码，改动量较大
- 前端需要复制并适配算力服务合同的页面模板（但页面结构复用度高）

### 可逆性
🟢 **高** — 纯新增功能，不影响任何现有系统。
