# ADR-024: 点位图机架 tab 化 + 点选 U 位上架 + 设备位置字段统一

## Status
Accepted（修订 ADR-022 的点位图展示方式；确认结构化位置字段为唯一录入通道）

## Context
ADR-022/023 上线后用户验收反馈：
1. **多机架横向排布不可用**：机房 10 个机架（A01~A10，另有 B/C 列机架会更多）全部横向排布时表格过宽，无法浏览。要求：点位图/仓库 tab 改为**按机架切换**的 tab（每个机架一个 tab，点击切换），"点位图" tab 取消
2. **上架操作重定义**：设备上架改为在点位图**点击空格 U 位 → 下拉搜索/点选设备**放入该格，U 位号自动填入（1 在最下，自下而上）。原仓库 tab 的"上架按钮→选机架"流程被替代
3. **位置字段重复**：设备表单同时存在 `rack_location` 自由文本与 `machine_room_id + rack_id + u_position` 结构化字段（ADR-021/022 增量导致），用户要求只保留一个

## Decision

### 1. 位置字段统一：保留结构化，rack_location 降级为只读存量
- **保留** `machine_room_id + rack_id + u_position`（设备表单唯一位置录入通道：所属机房 → 机架下拉联动 → U 位）。理由：可校验（同机架同 U 唯一 409）、可驱动点位图、可筛选聚合
- **废弃** `rack_location` 作为录入字段：设备新建/编辑表单（rentals/create.vue）移除该输入项
- **不删库**：`rack_location` 列与 API 参数保留（存量 22 台设备数据、合同/报表存量展示兼容），前端不再写入
- **统一展示**：新增前端工具函数 `formatRackLocation(record)`（`lib/rental.ts`）：
  - 有 `rack_name` → `{rack_name}-U{u_position}`（如 `A01-U12`）
  - 无 rack_name 但有 `rack_location` 存量文本 → 原样显示
  - 都无 → `—`
  - 应用点：设备列表"机架位置"列、设备详情"机架位置"、机房仓库 tab"当前位置"、上架信息展示、合同详情设备表位置列
- 已知限制（本轮不做）：设备列表页"机架位置"搜索框仍走后端 `rack_location` 文本参数（只搜得到存量数据）；contracts/create 复制设备时后端复制 rack_location——列入后续清理

### 2. 点位图 tab 化（machine-rooms/detail.vue）
- tab 结构：`A01 | A02 | … | A10 | 仓库（22）`——每个机架一个 tab（label=机架名，附通电状态小标识），"点位图"tab 删除
- 点击机架 tab：内容区只渲染**该单个机架**的点阵（U 位号列 + 设备格列两列），列宽可放宽
- 机架管理（添加机架按钮、当前机架的容量编辑/电源开关/删除）放内容区顶部工具栏（当前机架上下文）
- 顶部深蓝横幅保留，统计口径=**整个机房**（跨机架聚合，不变）
- 未定位 U 的在架设备提示（unlocated）保留在内容区底部

### 3. 点选 U 位上架（替代仓库 tab 上架按钮）
- 点位图**空 U 位格可点击**（视觉提示：hover 显示 "+"）→ 打开"放入设备"对话框：
  - 固定显示目标 `{机架名} · U{u}`（U 位自动取自点击的格，只读）
  - 设备选择 = 仓库未上架设备（`GET /api/rentals?warehoused=true`），带搜索框（`search` 参数按型号模糊）
  - 点选一台 → `PUT /api/rentals/{id}` 提交 `machine_room_id + rack_id + u_position`
  - 409 冲突提示保留（理论上空格不会冲突，防御性保留）
- **仓库 tab 移除"上架"按钮与旧上架对话框**（入口统一到点位图），仓库 tab 保留设备列表 + 详情跳转
- 已占用格点击跳设备详情（现状不变）

### 4. 后端配套（小改）
- `GET /api/machine-rooms/{room_id}/points` 响应新增 `unlocated: list[RackDeviceBrief]`：`machine_room_id=本机房 AND rack_id IS NOT NULL AND u_position IS NULL` 的设备（新数据不再写 rack_location，原"devices 前缀匹配 − u_cells"的前端算法对新数据失效，改为后端按 rack_id 视角提供）
- 机架删除保护改为：存在 `rack_id` 指向该机架的设备则 409（原前缀匹配保护保留为或条件，兼容存量）
- `u_cells` / 占用校验 / 409 语义均不变

## Consequences
**变容易的**：
- 单机架视图彻底解决横向宽度问题，任意数量机架/列（A/B/C）都可扩展
- 上架操作符合"看图找空位 → 点格子 → 塞设备"的巡检心智模型
- 位置数据单一事实来源，不再出现"文本写的 A01、结构化选的 B02"的矛盾

**变难的**：
- 上架多一次 tab 切换（从仓库看到设备 → 切到机架 tab 点格子）；换来操作语义统一
- 存量 22 台设备只有 rack_location 文本，点位图上全部显示"未上架"，需人工逐台指定机架+U（与 ADR-022 已声明的一次性整理成本相同）
- 展示点改造面广（6+ 页面），formatRackLocation 需逐一替换

## 可逆性
高：纯展示与流程调整 + 1 个只增响应字段；rack_location 列未动，回滚 = 前端恢复旧布局与旧上架对话框。

## 决策记录
- 2026-10-19：用户验收反馈三点（tab 化/点选上架/字段二选一），裁决保留结构化位置字段；ADR-022 点位图横向多机架布局被本 ADR 取代
