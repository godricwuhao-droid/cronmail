# ADR-029: 点位图业务逻辑修复（机柜断电叠加 + 详情返回 + 容量收缩校验）

## Status
Accepted

## Context
用户验收 ADR-027 视觉版后指出两个业务逻辑问题，并要求排查其他不合逻辑的设计：
1. 机柜断电后，柜内设备色块颜色无变化——断电状态对设备呈现零影响，与直觉相悖
2. 点位图点设备进详情后，返回回到设备列表而非点位图

## Decision

### 1. 机柜断电 → 柜内设备色块灰化叠加（纯视觉，不改数据）
- `cabinet.power_on = false` 时，该柜内**所有设备色块**加 CSS `filter: grayscale(1) opacity(0.55)`（保留原 4 色语义但整体灰暗化），并保留左侧状态条灰化
- 语义：**机柜断电是"空间状态"，设备状态是"资产状态"，两者正交**——断电不自动改设备 status（租赁中设备断电仍是租赁中），只叠加视觉警示（借鉴 Stratora 健康状态叠加哲学）
- 空格格区同样灰化（整列低饱和），与机柜组头灰点呼应
- 恢复通电立即还原（前端按 power_on 渲染，无数据迁移）
- 断电机柜**允许**继续点选上架（运营可预置设备），不做拦截

### 2. 详情页返回 → 回来源页
- 设备详情"返回"按钮改为 `router.back()`（有历史时回来源页：点位图/列表/合同均可）；无历史（直接 URL 进入）fallback `/rentals`
- 点位图跳详情保持 `router.push`（加历史栈），保证 back 可回

### 3. 机架容量收缩校验（排查补充）
- 后端：`PUT rack capacity_u` 若新容量 < 柜内设备最大占用上端（max(u_position + u_size - 1)）→ 400 `机架容量不能小于已占用的最大 U 位（U{max}）`
- 防止缩容后存在区间越界的"幽灵设备"（前端点位图按 capacity 行序渲染，越界设备会消失不可见）

### 4. 排查清单（本轮一并核查，发现问题另裁）
- "放入设备"对话框数据源是否覆盖"已定架未定位"设备（unlocated 能否从点位图换 U 位上架）
- 删除当前选中机柜/机架的 tab 回落
- 断电机柜上架是否需提示
- 横幅统计实时性

## Consequences
**变容易的**：断电一眼可见（整列灰暗）；返回心智恢复（从哪来回哪去）；容量不再可能缩到设备底下。
**变难的**：无——叠加是纯 CSS，返回是导航修正，校验是增量 400。

## 可逆性
高：均为增量修复，无数据模型变更。
