# ADR-025: 点位图 tab 单位改为机柜列（A列/B列/C列）

## Status
Accepted（部分取代 ADR-024 第 2 节"每机架一个 tab"的展示决策；ADR-024 的点选上架、位置字段统一、后端 unlocated 等决策不变）

## Context
ADR-024 上线后用户指出理解偏差：点位图 tab 化做成了"每个机架一个 tab"，但用户本意是**按机柜列分组**——A 列机架（A01~A10）应在内容区一起并排展示（与 ADR-023 横向布局一样），B 列、C 列的机架才作为上方 label 切换。机架命名规则为"字母前缀+编号"（A01、B01…），前缀字母即机柜列。

## Decision
1. **tab 单位 = 机柜列**：按 `rack.name` 首字母分组（A01/A02…→「A 列」，B01…→「B 列」）；首字母不是 A-Z 的机架归入「其他」列
   - tab label：`A列（10）`（列名+该机架列内机架数），末位 tab 仍为 `仓库（N）`
   - 新增机架（如 B-05）自动形成/并入对应列 tab，无需配置
2. **内容区**：渲染**当前列的全部机架**，恢复 ADR-023 的"每机架组两列（U位号列+设备格列）横向并排"布局，横向滚动
3. **横幅统计口径改为当前列**（与参考图"机架 A（…）共计74台设备"语义一致）：`{机房名}·{列名} 共计 N 台设备（型号统计…）`
4. **机架管理操作回到各机架表头**（编辑容量/电源状态/删除按钮，ADR-023 位置）；工具栏保留「添加机架」（新建时按 name 前缀自动归列）
5. 点选 U 位上架、unlocated 提示、仓库 tab、位置字段统一等 ADR-024 决策全部保留，不受本 ADR 影响

## Consequences
**变容易的**：
- 单列（如 A 列 10 机架）一屏内并排看全，符合"一列机柜 = 一面墙"的物理心智
- 列数增长（A/B/C…）时 tab 线性增长，列内机架再多也只是横向滚动
**变难的**：
- 列是纯命名约定（首字母），无数据模型支撑——机架重命名改前缀会"搬列"（但机架名本就只读，实际不发生）
- 非字母开头命名进「其他」列，观感略弱（可接受）

## 可逆性
高：纯前端分组与渲染调整，无数据变更、无接口变更。

## 决策记录
- 2026-10-19：用户指出 ADR-024 tab 粒度错误（应为机柜列而非单机架），本 ADR 修订展示层
