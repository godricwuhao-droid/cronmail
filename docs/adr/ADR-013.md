# ADR-013: 合同数据模型字段补全（算力服务 + 卫星数据）

## Status
Accepted — 已完成卫星数据合同（10 字段）和算力服务合同（4 字段）的补全

## Context

业务方需要为三大类合同（算力租赁、卫星数据、算力服务）提供列表导出 Excel 功能。导出字段共 14 列：

| # | 列名 | 说明 |
|---|------|------|
| 1 | 序号 | 导出时动态生成 |
| 2 | 所属类型 | 三大类合同名称 |
| 3 | 合同名称 | name |
| 4 | 合同类型 | 子类型（算力租赁=billing_model, 算力服务=contract_type, 卫星数据=新增） |
| 5 | 所属项目 | 新增 |
| 6 | 甲方 | 新增（卫星数据） |
| 7 | 乙方 | 新增（卫星数据） |
| 8 | 服务开始 | 新增（卫星数据） |
| 9 | 服务结束 | 新增（卫星数据） |
| 10 | 合同金额（元） | 新增（卫星数据） |
| 11 | 合同编号 | 已有 |
| 12 | 合同内容 | 新增 |
| 13 | 合同交付要求 | 新增 |
| 14 | 过程记录 | 新增 |

**算力租赁合同**（`Contract` 表）目前在生产环境中运行，涉及 Celery 定时任务、邮件发送、设备关联等核心链路，本轮**不动**，后续单独安排。

**算力服务合同**（`ComputeServiceContract`）和**卫星数据合同**（`SatelliteDataContract`）为纯归档型合同，无核心业务链路耦合，改动风险低，本轮优先补全。

## Decision

### 1. SatelliteDataContract 新增字段

新增 10 个字段，全部手动填写：

| 字段 | 类型 | 说明 |
|------|------|------|
| `contract_type` | String(30), nullable | 合同子类型（自由文本，由用户自行填写） |
| `project_name` | String(255), nullable | 所属项目 |
| `party_a_name` | String(255), nullable | 甲方名称 |
| `party_b_name` | String(255), nullable | 乙方名称 |
| `start_date` | Date, nullable | 服务开始日期 |
| `end_date` | Date, nullable | 服务结束日期 |
| `amount` | Numeric(12,2), nullable | 合同金额 |
| `contract_content` | Text, nullable | 合同内容 |
| `delivery_requirements` | Text, nullable | 合同交付要求 |
| `process_records` | Text, nullable | 过程记录 |

### 2. ComputeServiceContract 新增字段

新增 4 个字段（甲乙方、金额、日期、合同类型已存在）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `project_name` | String(255), nullable | 所属项目 |
| `contract_content` | Text, nullable | 合同内容 |
| `delivery_requirements` | Text, nullable | 合同交付要求 |
| `process_records` | Text, nullable | 过程记录 |

### 3. 字段语义说明

- `contract_content`：合同主要内容概述或长文本描述
- `delivery_requirements`：合同交付标准/要求
- `process_records`：合同执行过程中的记录，如问题、变更说明等
- 三个字段均为 **Text 长文本**，由用户在编辑表单中手动输入，不做自动关联/聚合

### 4. 导出列的"合同类型"映射

| 合同大类 | 映射字段 |
|----------|---------|
| 算力租赁 | `billing_model`（monthly/quarterly/yearly） |
| 卫星数据 | `contract_type`（新增，自由文本） |
| 算力服务 | `contract_type`（sales/procurement） |

### 5. 调度策略

- **本轮**（ADR-013）：完成算力服务合同 + 卫星数据合同的字段补全，不触及算力租赁
- **后续**（ADR-014 预计）：补全算力租赁合同的 project_name、contract_content、delivery_requirements、process_records

## Consequences

### 变容易了
- 卫星数据合同从仅 4 个字段扩展到 14 个字段，与算力服务合同字段完整性对齐
- 导出功能后续实现时，三类合同的字段映射逻辑一致
- 算力租赁核心链路零风险，不受本轮改动影响

### 变难了
- 前后端需要改动：模型、Schema、API、表单（创建/编辑）、列表展示
- 需要执行 Alembic 数据库迁移
- 卫星数据合同的 contract_type 为自由文本（非枚举），导出时按原样输出，不做校验

### 可逆性
🟢 **高** — 所有新增字段均为 nullable，不影响现有数据；如需回滚只需删除字段，不破坏已有记录。
