# ADR-015: 智能合同解析 Agent（Word 文档）

## Status
Accepted — 后端 contract_parser 模块 + 前端智能解析按钮 完成

## Context

用户在新建合同页面手动填写字段较多（算力服务合同 15+ 字段），效率低。利用本地已有的 Qwen3.6-27B 多模态模型，上传 Word 合同文件后自动提取关键字段填充表单。

## Decision

### 1. 技术方案

| 层 | 选型 | 说明 |
|----|------|------|
| 文本提取 | `python-docx` | 逐段落提取 Word 文本 |
| AI 解析 | 本地 Qwen3.6-27B | `http://192.168.180.66:34000`，兼容 OpenAI SDK |
| 文件范围 | 仅 `.docx` | 不做 PDF（扫描件为主，OCR 成本太高） |

### 2. 架构

```
POST /api/contracts/parse
  multipart/form-data: file + contract_type

┌─ 后端新模块 src/contract_parser/ ─┐
│  api.py        → 接收文件           │
│  services.py   → 提取文本 → LLM    │
│  prompts.py    → Prompt 模板       │
└──────────────────────────────────┘

返回: JSON fields → 前端自动填表
```

- 纯新增模块，**零侵入**现有合同 CRUD
- 文件仅用于本次解析，不落库
- 解析失败返回错误提示，不阻塞手动填写

### 3. Prompt 策略

按合同类型返回不同字段集，要求严格 JSON 输出，找不到填 null。

### 4. 新增依赖

- `python-docx` — Word 文本提取
- `openai` — 调用本地 LLM（兼容 OpenAI SDK）

## Consequences

### 变容易了
- 合同创建效率提升，减少手动输入错误
- 数据不出内网，无合规风险
- 模块独立，后续扩展到卫星数据合同只需改 Prompt

### 变难了
- 大合同（100+ 页）可能超出 LLM context，需截断
- 非标准合同格式可能导致提取准确率下降

### 可逆性
🟢 **高** — 纯新增模块，不影响任何现有功能。
